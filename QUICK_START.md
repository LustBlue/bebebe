# Краткое руководство по запуску ProjectFlow

Документ предназначен для быстрого запуска и проверки работоспособности
системы. Подробная инструкция по настройке окружения приведена в
[INSTALL.md](INSTALL.md), описание запросов к API — в
[API_TESTING.md](API_TESTING.md).

## 1. Требования

* Python 3.10 или новее (проект проверен на Python 3.10–3.12);
* установленный интерпретатор в переменной `PATH`;
* внешние библиотеки для базового запуска **не требуются**.

## 2. Запуск за три команды

```bash
python run.py --init-db      # создать схему базы данных
python run.py --demo-data    # наполнить демонстрационными данными (необязательно)
python run.py                # запустить сервер на http://127.0.0.1:5000
```

После запуска доступны:

| Адрес | Назначение |
|---|---|
| http://127.0.0.1:5000/ | веб-интерфейс пользователя |
| http://127.0.0.1:5000/api | справочник по конечным точкам API |
| http://127.0.0.1:5000/api/health | проверка работоспособности сервиса |

## 3. Учётные записи демонстрационных данных

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `Admin123456` | администратор |
| `manager` | `Manager123456` | менеджер |
| `executor` | `Executor123456` | исполнитель |

## 4. Проверка работоспособности

```bash
# Автоматические тесты (pytest не требуется)
python -m tools.run_tests

# Сквозная проверка через REST API (сервер должен быть запущен)
python tools/smoke_test.py --base-url http://127.0.0.1:5000
```

Ожидаемый результат: все автоматические тесты пройдены; сквозная проверка
подтверждает регистрацию, вход, создание проекта и задачи, изменение статуса,
формирование отчёта и экспорт в PDF и Excel.

## 5. Что можно проверить в системе

1. **Модуль авторизации** — регистрация пользователя, вход, получение данных
   текущего пользователя, разграничение доступа по ролям.
2. **Модуль задач** — создание проекта и задачи, назначение исполнителя,
   проведение задачи по статусам «новая → в работе → на проверке → завершена».
3. **Модуль отчётов** — формирование отчёта по исполнителю, по проекту и за
   период, экспорт отчёта в PDF и Excel.
4. **Обработка ошибок** — попытка выполнения операции без токена (HTTP 401),
   недоступная для роли операция (HTTP 403), запрещённый переход статуса
   (HTTP 400), неизвестный маршрут (HTTP 404).

## 6. Частые вопросы

**Нужно ли устанавливать Flask или SQLAlchemy?**
Нет. HTTP-сервер построен на стандартной библиотеке (`http.server`),
хранилище — SQLite через модуль `sqlite3`.

**Почему тесты запускаются не через pytest?**
Проект рассчитан на работу в изолированной среде без доступа к индексу
пакетов PyPI, поэтому поставляется встроенный запускающий модуль
`tools/run_tests.py`. Если pytest установлен, набор запускается и через него:
`python -m pytest tests/ -v`.

**Где хранится база данных?**
По умолчанию в файле `projectflow.db` в корневом каталоге проекта. Путь можно
изменить переменной окружения `DATABASE_PATH`.

**Как изменить порт сервера?**
`python run.py --port 8080` либо переменной окружения `PORT`.

**Как экспортировать отчёт в Excel?**
Установить `openpyxl` (`pip install openpyxl`). Экспорт в PDF работает всегда —
генератор PDF входит в состав проекта.
