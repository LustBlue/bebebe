## 1. Инспектирование кода

### 1.1. Методика статического анализа

Инспектирование исходного кода выполнено собственным статическим анализатором
`tools/inspect_code.py`. Инструмент не требует установки внешних линтеров: он
разбирает файлы средствами стандартной библиотеки (`ast`, `tokenize`, `re`) и
реализует правила flake8 и pylint, отобранные для данного проекта. Правила
согласованы с конфигурациями `.flake8` (максимальная длина строки — 100 символов)
и `.pylintrc` (соглашения об именовании, исключения для методов HTTP-обработчика).

Анализатор проверяет каталоги `src/`, `tests/` и `tools/`, исключая `__pycache__`,
`.git`, `htmlcov` и `.pytest_cache`. Реализованы следующие правила:

| Правило | Содержание проверки |
|---|---|
| `E501` | превышение длины строки (норма — не более 100 символов) |
| `W291` | пробелы в конце строки |
| `W292` | отсутствует перевод строки в конце файла |
| `W191` | символ табуляции в отступе |
| `D100`, `D101`, `D103` | отсутствует docstring модуля, класса, функции |
| `N801`, `N802`, `N803` | именование класса, функции, аргумента |
| `F401` | неиспользуемый импорт |
| `E722` | «голый» `except` без указания класса исключения |
| `W0707` | перевыброс исключения без конструкции `raise ... from` |
| `C901`, `R0913` | цикломатическая сложность и число аргументов выше порога |
| `B105` | возможный секрет (пароль, токен, ключ) в строковом литерале |
| `E999`, `E902` | синтаксическая ошибка, ошибка чтения файла |

Каждому замечанию присваивается критичность: `high`, `medium` или `low`.
Замечания пороговых правил (`C901`, `R0913`) и замечания, для которых в
`ACCEPTED_DEVIATIONS_BY_FILE` зафиксировано обоснование, относятся к категории
**согласованных отступлений** и не считаются неустранёнными дефектами.

Результаты двух прогонов сохранены в машинно-читаемом виде и приложены к отчёту:

* `reports/inspection_before.json` — состояние до исправлений;
* `reports/inspection_after.json` — состояние после исправлений.

## 3. Статический анализ PDF-отчётов

PDF-отчёты формируются собственным генератором `src/report_module/pdf_writer.py`
без внешних библиотек. Для контроля корректности файла применяется анализатор
`tools/verify_pdf.py`, который разбирает PDF побайтово и проверяет:

| Проверка | Содержание |
|---|---|
| Сигнатура `%PDF` | файл начинается с корректной сигнатуры `%PDF-1.4` |
| Маркер конца файла | файл завершается маркером `%%EOF` |
| Таблица `xref` | таблица перекрёстных ссылок присутствует, ключ `startxref` указывает на её начало |
| Смещения объектов | каждая запись `n` таблицы `xref` указывает на реальное начало объекта вида `<номер> 0 obj` |
| Обязательные объекты | присутствуют каталог (`/Type /Catalog`) и дерево страниц (`/Type /Pages`); число объектов страниц совпадает с `/Count` |
| Шрифты и кодировка | объявлены шрифты `/Helvetica`, `/Helvetica-Bold`, `/Courier` и кодировка `/WinAnsiEncoding` |
| Корректность `/Length` | длина каждого потока совпадает с фактическим размером данных, поток распаковывается без ошибок `zlib` |
| Потоки `FlateDecode` | сжатые потоки содержимого распаковываются и начинаются с оператора `BT` |
| Текстовые операторы | присутствуют операторы `BT`/`Tj`, извлекаемые строки декодируются |
| Кириллица WinAnsi | текстовые строки в кодировке WinAnsi корректно декодируются в кириллицу (включая `Ё`/`ё`) |

Запуск проверки:

```
python tools/verify_pdf.py reports/report.pdf
python tools/verify_pdf.py reports/
```

Проверка выполняется для всех PDF-файлов каталога `reports`; код возврата равен
нулю, если структура всех файлов корректна. Текущий результат — **все проверки
пройдены**: структура сформированных отчётов соответствует спецификации PDF,
сжатые потоки распаковываются, кириллический текст извлекается без потерь.

## 4. Проверка вёрстки диаграмм

Вёрстка диаграмм контролируется инструментом `tools/render_diagrams.py`.
Инструмент рассчитывает ограничивающие рамки всех элементов SVG и проверяет
четыре группы условий:

1. **Элементы помещаются на полотно.** Прямоугольники, тексты, линии и кривые
   не выходят за границы области диаграммы (заданы атрибутами `width`/`height`
   или `viewBox`).
2. **Текст внутри блоков не выходит за границы блока.** Для каждой подписи
   ширина вычисляется по метрикам реального шрифта с поддержкой кириллицы, а
   затем проверяется, что рамка текста целиком лежит внутри прямоугольника
   соответствующего блока.
3. **Подписи переходов не накладываются на блоки и друг на друга.** Рамки
   подписей проверяются на пересечение с рамками блоков и между собой.
4. **Кривые и линии не пересекают блоки.** Для кривых Безье (команды `Q` и `C`)
   и прямых отрезков проверяется отсутствие прохождения через прямоугольники
   блоков, которые они не должны пересекать.

Запуск проверки:

```
python tools/render_diagrams.py
python tools/render_diagrams.py --png diagrams/png
```
