## Раздел 3. Математическое моделирование

### 3.1 Диаграмма состояний задачи

Разработана формальная модель конечного автомата (FSM) для управления статусами задач:

**Состояния:** {new, in_progress, review, completed, rejected}

**Граф переходов:**
```
new → in_progress → review → completed
  ↓                   ↓
rejected ←───────────┘
  ↓
new (restart)
```

**Свойства модели:**
- ✅ Детерминированность
- ✅ Достижимость всех состояний
- ✅ Безопасность (completed — конечное состояние)
- ✅ Восстанавливаемость (rejected → new)

**Реализация:**
- `src/task_module/__init__.py` — словарь `VALID_STATUS_TRANSITIONS`
- Валидация переходов при изменении статуса
- История всех переходов в таблице `task_history`

### 3.2 ER-диаграмма базы данных

Спроектирована схема базы данных в 3NF:

**Сущности:**
- Users (пользователи)
- Projects (проекты)
- Tasks (задачи)
- Reports (отчёты)
- Task_History (история задач)

**Связи:**
- Users (1) → (N) Projects
- Users (1) → (N) Tasks (created_by)
- Users (1) → (N) Tasks (assigned_to)
- Projects (1) → (N) Tasks
- Tasks (1) → (N) Task_History

**Нормализация:**
- ✅ 1NF: Все атрибуты атомарны
- ✅ 2NF: Нет частичных зависимостей
- ✅ 3NF: Нет транзитивных зависимостей

### 3.3 Граф зависимостей модулей

Построен ориентированный ациклический граф (DAG):

```
REST API
  ↓
AuthModule, TaskModule, ReportModule
  ↓
Core (Security, Config, Validation)
  ↓
Database
```

**Уровни абстракции:**
- Level 4: Presentation (REST API)
- Level 3: Business Logic (модули)
- Level 2: Shared Services (Core)
- Level 1: Data Access (Database)

### 3.4 RBAC модель

Формальная модель управления доступом:

**RBAC = (U, R, P, UA, PA)**

**Роли:** {admin, manager, executor}

**Матрица привилегий:**
- Admin: полный доступ
- Manager: управление проектами и задачами
- Executor: работа со своими задачами

**Документ:** `docs/mathematical_models.md`
