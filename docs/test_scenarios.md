## 1. Сценарии модуля авторизации (AuthModule)

### Сценарий 1.1: Успешная регистрация пользователя

**Предусловия:**
- Система доступна
- База данных инициализирована
- Пользователь с таким username и email ещё не существует

**Шаги:**
1. Отправить POST запрос на `/api/auth/register` с данными:
   ```json
   {
     "username": "newuser",
     "email": "newuser@example.com",
     "password": "SecurePass123",
     "role": "executor"
   }
   ```
2. Получить ответ от сервера

**Ожидаемый результат:**
- HTTP статус: 201 Created
- Ответ содержит данные созданного пользователя (без пароля)
- Пользователь добавлен в базу данных

**Фактический результат:** ✅ Пройден

---

### Сценарий 1.2: Регистрация с дубликатом username

**Предусловия:**
- В базе существует пользователь с username "existinguser"

**Шаги:**
1. Отправить POST запрос на `/api/auth/register` с username "existinguser"

**Ожидаемый результат:**
- HTTP статус: 400 Bad Request
- Сообщение об ошибке: "Пользователь с таким именем или email уже существует"

**Фактический результат:** ✅ Пройден

---

### Сценарий 1.3: Успешный вход в систему

**Предусловия:**
- Пользователь зарегистрирован и активен

**Шаги:**
1. Отправить POST запрос на `/api/auth/login` с данными:
   ```json
   {
     "username_or_email": "testuser",
     "password": "SecurePass123"
   }
   ```

**Ожидаемый результат:**
- HTTP статус: 200 OK
- Ответ содержит:
  - access_token
  - refresh_token
  - user (данные пользователя)

**Фактический результат:** ✅ Пройден

---

### Сценарий 1.4: Вход с неверным паролем

**Предусловия:**
- Пользователь существует

**Шаги:**
1. Отправить POST запрос на `/api/auth/login` с неверным паролем

**Ожидаемый результат:**
- HTTP статус: 401 Unauthorized
- Сообщение: "Неверное имя пользователя или пароль"

**Фактический результат:** ✅ Пройден

## 2. Сценарии модуля задач (TaskModule)

### Сценарий 2.1: Создание новой задачи

**Предусловия:**
- Пользователь авторизован
- Проект существует

**Шаги:**
1. Отправить POST запрос на `/api/tasks` с JWT токеном:
   ```json
   {
     "title": "Новая задача",
     "description": "Описание задачи",
     "project_id": 1,
     "priority": "high"
   }
   ```

**Ожидаемый результат:**
- HTTP статус: 201 Created
- Задача создана со статусом "new"
- Создана запись в task_history

**Фактический результат:** ✅ Пройден

---

### Сценарий 2.2: Переход задачи new → in_progress

**Предусловия:**
- Задача существует в статусе "new"

**Шаги:**
1. Отправить PATCH запрос на `/api/tasks/{id}/status`:

   ```json
   {
     "status": "in_progress"
   }
   ```

**Ожидаемый результат:**
- HTTP статус: 200 OK
- Статус задачи изменён на "in_progress"
- Добавлена запись в историю

## 7. Граничные случаи

### 7.1 Пустые значения
- ✅ Пустой username → ValidationError
- ✅ Пустой email → ValidationError
- ✅ Пустой title задачи → ValidationError

### 7.2 Длинные значения
- ✅ Username > 50 символов → ValidationError
- ✅ Title > 150 символов → ValidationError

### 7.3 Несуществующие ID
- ✅ Несуществующий project_id → ValidationError
- ✅ Несуществующий user_id → ValidationError

### 7.4 Безопасность
- ✅ Невалидный JWT токен → AuthenticationError
- ✅ Истёкший токен → AuthenticationError
- ✅ Отсутствующий токен → 401 Unauthorized
