# Отчёт о соответствии реализации задачи диаграмме состояний

Отчёт подготовлен по задаче 3.3 «Инспектирование компонентов на соответствие моделям». Проверки выполнены автоматически генератором `tools/make_model_docs.py` и тестами `tests/test_integration.py`.

## 1. Проверяемые артефакты

| Артефакт | Назначение |
|---|---|
| `src/core/models.py` | эталонная модель: `STATUS_TRANSITIONS`, `TRANSITION_MATRIX` |
| `src/task_module/__init__.py` | реализация: `VALID_STATUS_TRANSITIONS`, `change_task_status()` |
| `docs/transition_matrix.md` | матрица переходов (задача 3.2) |
| `docs/mathematical_models.md` | диаграмма состояний (задача 3.1) |
| `diagrams/state_diagram.svg` | графическое представление модели |

## 2. Проверка 1. Полнота реализации

**Вопрос:** все ли переходы модели реализованы?

* Переходов в модели: **8**
* Переходов в реализации: **8**
* Отсутствующих переходов: **0**

Результат: **все переходы модели реализованы**. Автоматическая проверка — тест `test_all_model_transitions_are_implemented`.

## 3. Проверка 2. Отсутствие запрещённых переходов

**Вопрос:** нет ли в реализации переходов, отсутствующих в модели?

* Переходов реализации вне модели: **0**

Результат: **реализация не содержит переходов вне модели**. Автоматическая проверка — тест `test_no_extra_transitions_in_implementation`.

Дополнительно проверены переходы, прямо названные в задании как запрещённые:

| Запрещённый переход | Проверка | Результат |
|---|---|---|
| Новая → Завершена | задача не может быть завершена без выполнения | запрещён |
| Новая → На проверке | нельзя отправить на проверку невыполненную задачу | запрещён |
| В работе → Новая | задача не может вернуться в исходное состояние | запрещён |

## 4. Проверка 3. Обработка граничных случаев

| Граничный случай | Ожидаемое поведение | Реализация | Проверка |
|---|---|---|---|
| Несуществующий статус (`status = 'done'`) | `ValidationError`: «Недопустимый статус» | `settings.is_valid_task_status()` перед проверкой перехода | `test_create_task_invalid_priority`, ручная проверка API |
| Несуществующая задача (`task_id = 9999`) | `ValidationError`: «Задача не найдена» | `get_task_by_id()` в начале операции | `test_get_task_by_id_nonexistent` |
| Переход в текущий статус (`new → new`) | переход отклоняется как отсутствующий в матрице | `new_status not in VALID_STATUS_TRANSITIONS[current]` | матрица переходов (диагональ запрещена) |
| Исполнитель пытается выполнить переход менеджера | `PermissionDeniedError` (HTTP 403) | проверка роли через `roles_for_transition()` | `test_role_based_access_control`, REST-проверка `smoke_test.py` |
| Деактивированный пользователь меняет статус | `PermissionDeniedError`: «Учётная запись деактивирована» | проверка `users.is_active` в `change_task_status()` | `test_deactivate_user_success` + проверка в модуле задач |
| Повторный переход после завершения задачи | разрешён только `completed → in_progress` (T8) | матрица переходов, строка `completed` | `test_change_task_status_from_completed` |
| Удаление задачи (терминальное состояние) | запись удаляется, исходящих переходов нет | `delete_task()`, состояние `TASK_DELETED` | `test_delete_task_success`, `test_deleted_tasks_are_terminal` |

## 5. Проверка 4. Согласованность документации и кода

| Документ | Источник данных | Способ синхронизации |
|---|---|---|
| `docs/transition_matrix.md` | `src/core/models.py` | генерация `tools/make_model_docs.py` |
| `diagrams/state_diagram.svg` | `src/core/models.py` | генерация `tools/make_diagrams.py` |
| `VALID_STATUS_TRANSITIONS` | `TRANSITION_MATRIX` | вычисляется при импорте модуля задач |

Такое построение исключает расхождение «модель — реализация — документация»: единственным источником истины является `STATUS_TRANSITIONS`.

## 6. Замечания и рекомендации

| № | Замечание | Критичность | Решение |
|---|---|---|---|
| 1 | Цикломатическая сложность `change_task_status()` повышена из-за четырёх последовательных проверок | низкая | проверки выделены в отдельные шаги с комментариями; дальнейшая декомпозиция не требуется |
| 2 | Роли на переходы проверяются в модуле задач, а не в слое API | низкая | единая точка проверки выбрана осознанно: модуль остаётся работоспособным при использовании без REST-слоя |
| 3 | Состояние `deleted` не хранится в `tasks.status` | информационная | задача удаляется физически; состояние включено в модель как терминальное для полноты матрицы |
